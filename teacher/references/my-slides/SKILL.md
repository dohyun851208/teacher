# My Slides

나만의 스타일로 완성된 HTML 프레젠테이션 생성기.

**기본 스타일:** Korean Edu Pastel — 파스텔 블루그레이 배경, 크림 카드, Plus Jakarta Sans, 보라 포인트
**기본 언어:** 한국어

## Core Principles

1. **Zero Dependencies** — 단일 HTML 파일, CSS/JS 인라인. npm 없음.
2. **Viewport Fitting (필수)** — 모든 슬라이드는 100vh에 딱 맞아야 함. 슬라이드 내 스크롤 없음.
3. **Korean Edu Pastel 기본** — 스타일 탐색 없이 바로 생성. 요청 시 변경 가능.
4. **드로잉 캔버스 항상 포함** — 마우스 드래그로 하이라이터 효과. 슬라이드 전환 시 자동 초기화.
5. **clamp() 필수** — 모든 폰트 크기·여백은 clamp() 사용.
6. **인라인 편집 항상 포함 (점 버튼 토글)** — 우측 상단 작은 검은 점(10px 원형 버튼, `top:30px; right:30px` — 카드 안쪽 여백으로 들어오게 배치). 첫 클릭 → 편집 모드 진입(점이 보라색, 텍스트 클릭 시 바로 편집). 다시 클릭 → 저장 + 편집 종료(점이 검은색 복귀). 저장 방식: 각 요소 innerHTML을 **안정된 ID**(`slideId-e숫자` 자동생성 또는 `data-edit="커스텀ID"` 지정값) 키로 localStorage에 JSON 저장, 페이지 로드 시 자동 복원. **슬라이드 추가/삭제/이동에도 편집 내용이 안 날아감** (index 기반이 아님). 편집 중 ESC = 포커스 해제, 방향키 네비게이션 자동 차단.
7. **접근성·짧은 viewport 안전장치 필수** — `prefers-reduced-motion`(애니메이션 단축, 기본판은 RESPONSIVE 섹션에 내장), 짧은 viewport 단계 `@media (max-height: 680px/600px/500px)`로 작은 노트북·태블릿 가로 대응, 카드 max 사이즈로 4K 모니터에서 카드 비대화 방지. 구체 CSS는 [html-template.md](html-template.md)의 RESPONSIVE 섹션 + "추가 안전장치 (보강)" 섹션 참조.
8. **애니메이션은 의도가 있을 때만** — 분위기별 진입/배경/인터랙션 패턴은 [animation-patterns.md](animation-patterns.md) 참조. 발표의 흐름을 돕는 데만 쓰고, 반복 모션이나 본문이 흔들리는 효과는 피한다.

## 슬라이드별 테마 색상 오버라이드

특정 슬라이드에 고유 배경색을 적용할 수 있다:

```css
#sN { background: linear-gradient(135deg, #색상1, #색상2); }
#sN .hr { background: #포인트색; }
#sN .hl { background: linear-gradient(135deg, #색1, #색2); }
#sN .sec-title em { color: #포인트색; }
```

플랫폼 배지 색상 클래스: `.pb-gyeonggi` (보라), `.pb-busan` (하늘), `.pb-chungbuk` (초록), `.pb-chungnam` (로즈), `.pb-gyeongnam` (틸)

## Viewport Fitting 규칙

- 모든 `.slide`에 `height: 100vh; height: 100dvh; overflow: hidden;` 필수
- 폰트/여백은 모두 `clamp(min, preferred, max)` 사용
- 이미지: `max-height: min(50vh, 400px)` (insight-icon은 `clamp(250px, 50vh, 480px)`)
- `prefers-reduced-motion` 지원 포함
- 슬라이드 내용 넘침 → 슬라이드 분리, 절대 크램하지 않음

## 주의사항 (두 파일 비교에서 발견)

- **preview-btn 배경**: `.hl`(어두운 그라디언트) 안에서는 `rgba(255,255,255,0.3)`, 밝은 배경(insight-kw 등)에서는 `rgba(0,0,0,0.07)` 사용
- **canvas z-index**: 4000 (모달은 9000이므로 그 아래)
- **드로잉 차단**: 모달 열려있을 때 mousedown 이벤트에서 그리기 차단 처리 필수
- **슬라이드 ID**: 연속이 아니어도 됨 (s1, s2, s3, s7, s9... 처럼 건너뛰기 가능). 중간 삽입 시 `s2b` 같은 문자 접미사 OK. `TOTAL`은 `slides.length`로 자동 계산되므로 신경 쓸 필요 없음.

## 콘텐츠 편집 판단력

소스 내용을 그대로 슬라이드에 옮기지 말 것. 각 슬라이드에서 해당 내용이 **그 자리에 맞는가**를 먼저 판단한다.

### 타이틀 슬라이드 통계/키워드 선정 기준
- 타이틀 페이지 stat/키워드는 **청중이 문맥 없이도 의미를 이해**할 수 있어야 함
- 나쁜 예: "99% 한글완성도" → 한글 깨짐 해소 방법의 세부 수치인데, 타이틀에서는 맥락이 전혀 없음
- 좋은 예: "3가지 실질적 활용", "환각 없는 AI", "무료 사용" → 설명 없이도 직관적으로 이해됨
- 통계는 그 숫자만 봐도 임팩트가 있어야 함. 맥락이 필요한 수치는 해당 섹션 슬라이드에서만 사용

### 슬라이드별 콘텐츠 배치 원칙
- **타이틀**: 발표의 핵심 가치와 범위를 한눈에 — 세부 구현 정보 금지
- **콘텐츠 슬라이드**: 해당 주제의 핵심만 — 다른 슬라이드 내용이 섞이지 않게
- 소스에 있는 내용이라도 그 슬라이드의 흐름과 맞지 않으면 생략하거나 적절한 슬라이드로 이동

### 모르는 내용은 추론하지 말 것
- 소스에 불분명한 용어나 수치가 있으면 그대로 사용하지 말고, 해당 맥락을 파악해서 의미 있는 위치에 배치
- 의미가 불분명한 stat은 타이틀/요약 슬라이드에서 제외하고 해당 내용 슬라이드에서만 설명과 함께 사용

### 이미지 내 중복 제목 처리 (PDF/PPT에서 추출한 이미지)

PDF나 PPT에서 페이지 단위로 뽑은 이미지는 상단에 원본 챕터 제목(예: "① 생성형 AI의 태동")이 박혀있는 경우가 많다. 슬라이드 `sec-title`과 **중복**되므로 반드시 잘라내야 한다.

**절차 (이미지 한 장 한 장 개별 측정 필수):**

1. **Read 도구로 이미지를 실제로 본다** — 절대 "대충 15%" 같은 일괄 적용 금지. 이미지마다 제목부 비율이 다름.
2. **제목부 정확한 세로 비율 측정** — 상단 라벨(둥근 번호 뱃지 + 텍스트) + 그 아래 구분선(있으면)까지의 세로 길이를 이미지 전체 높이의 %로 계산.
3. **본문 콘텐츠는 절대 건드리지 않도록 보수적으로** — 이미지 자체에 큰 본문 타이틀이 있는 경우(예: "전통적인 코딩 vs. 바이브 코딩")와 중복 제목부 사이 간격이 좁으면, 본문 타이틀이 잘리지 않는 최대치만 자른다. 과다 절단보다 약간 남기는 게 낫다.
4. **CSS 적용 방식** — `object-view-box: inset(N% 0% 0% 0%)`을 **인라인 style로 각 `<img>`에 개별 지정**. 공통 클래스에 일괄 적용 금지 (이미지마다 값이 다르니까).

```html
<!-- 이미지별로 직접 측정한 값을 인라인으로 -->
<img class="pdf-img" style="object-view-box:inset(10% 0% 0% 0%)" src="images/page-04.png" alt="...">
<img class="pdf-img" style="object-view-box:inset(12% 0% 0% 0%)" src="images/page-12.png" alt="...">
```

**브라우저 지원**: `object-view-box`는 Chrome 104+, Safari 16.4+, Edge 104+ (2022~2023년 지원 시작, 2026년 현재 안정). 다른 방식(clip-path, transform scale)은 중심 이동·확대 왜곡이 생기므로 `object-view-box` 우선.

### 최신 정보만 사용 — 무조건 WebSearch 실행 (예외 없음)

**⛔ 내부 지식(학습 데이터)을 "최신"이라고 가정하는 것은 금지다.** 학습 cutoff 이후의 버전 번호·모델명·가격·이벤트는 모델 안에 없다. 기억에 있어도 믿지 말 것 — 기억은 과거 시점의 스냅샷이고, 그 이후에 업데이트됐을 수 있다.

**🚨 무조건 규칙: 아래 카테고리의 정보가 슬라이드에 한 글자라도 들어가면, WebSearch를 반드시 먼저 실행한다. 예외 없음. "확신한다"도 안 됨. "자주 아는 내용"도 안 됨. "바로 전에 찾았다"도 다시 실행.**

**강제 절차 — 시점 종속 정보를 슬라이드에 쓰기 직전에 반드시 실행:**

1. **WebSearch를 무조건 실행** (건너뛰기 절대 금지) — 아래 카테고리의 값이 슬라이드에 들어가면:
   - AI 모델 버전/이름 (GPT/Claude/Gemini/Grok/Llama/…)
   - 벤치마크 점수, 순위, 시장 점유율
   - 이벤트 연도·월 (IMO, 국제 대회, 릴리스일)
   - 가격, 무료/유료 정책
   - "최신/현재/요즘" 같은 단어가 수식하는 모든 정보

2. **확신 있어도 검색**. "나는 알아" 금지. 2026-04-15 기준 나는 GPT-5.4 / Claude Opus 4.6 / Gemini 3.1 Pro / Grok 4.20 Beta 2가 플래그십이라는 걸 **학습 데이터에서는 몰랐고**, WebSearch 해야만 알 수 있었음. 이 구조적 한계를 인정하고 늘 검색할 것.

3. **병렬로 한 번에 검색**. 4개 프로바이더면 4개 WebSearch를 한 메시지에 병렬 호출.

4. **결과 교차 검증** — 하나의 소스가 아닌 2~3개 결과로 같은 숫자가 나오는지 확인. 블로그 추측은 피하고 공식/주요 테크 매체 중심으로.

5. **날짜 기준점 활용** — `<currentDate>` 태그에 있는 오늘 날짜를 출발점으로. "latest X April 2026" 같은 월 단위 쿼리 사용.

**안티패턴 (실제로 내가 실수한 사례):**
> ❌ "2026년 4월 기준 최신으로 쓰자 → 내 기억으로는 GPT-5, Claude 4, Gemini 2.5, Grok 4일 것" → 슬라이드에 기록
> ✅ "2026년 4월 기준 → WebSearch 4개 동시 호출 → GPT-5.4, Claude Opus 4.6, Gemini 3.1 Pro, Grok 4.20 Beta 2 확인 → 슬라이드에 기록"

**슬라이드에 연도가 들어가면 currentDate와 비교 체크:**
- 과거 사실: 발생 연도 그대로 (예: "2025년 AI가 IMO 금메달" — 실제 2025년 사건)
- 현재 시점 표현("현주소", "현재"): today 연도로 (예: 2026-04-15 오늘이면 "2026년 AI의 현주소")

## 폰트 크기 사용 원칙

프레젠테이션은 웹페이지가 아니라 화면·프로젝터로 보는 자료. 텍스트가 작으면 전달력이 떨어진다.

**변수별 용도 구분:**
| 변수 | 크기 (max) | 용도 |
|------|-----------|------|
| `--t1` | ~4.5rem | 타이틀 슬라이드 제목 |
| `--t2` | ~1.8rem | 타이틀 부제목 |
| `--t3` | ~1.4rem | 콘텐츠 슬라이드 소제목 (sec-title, flow-title) |
| `--tb` | **1.45rem** | 본문 텍스트 — blist, grp-desc, step-desc, flow-desc, pcard-desc 등 읽히는 내용 전부 |
| `--ts` | **1.05rem** | 라벨·뱃지·메타 전용 — sec-label, badge, 보조 정보 |

**규칙:**
- **읽히는 본문은 반드시 `--tb` 이상** — `--ts`를 본문에 쓰는 것 금지
- `--ts`는 sec-label, badge, 카드 내 보조 라벨처럼 "핵심 정보가 아닌 것"에만 사용
- 컴포넌트 추가 시 body text = `var(--tb)`, label = `var(--ts)` 원칙 유지

## 타이틀·슬로건 작성 규칙

**명사형으로 끝낼 것** — PPT는 전달력이 생명. 동사형 어미("~할 수 있다", "~한다", "~이런 걸 할 수 있다")는 늘어지고 약함.

**적용 범위:**
- `sec-title` (슬라이드 제목)
- `.hl-v` (한 줄 요약·슬로건)
- `.grp-title` (그룹 카드 제목)
- `.insight-kw`, `.module-name` 등 키워드성 텍스트

**좋은 예:** "실질적 활용 3가지", "한글 깨짐 해소 방법", "3단계 워크플로우", "핵심 장점", "사람 최상위권 수준의 추론, 이미 상용 AI에 내장", "코딩마저 AI의 영역으로 편입"

**나쁜 예:** "이런 걸 할 수 있다", "더 강력하게 만드는 법", "이렇게 활용한다"

- `sec-title`의 메인 키워드는 `em` 태그로 포인트색 강조

### 금지 표현 (촌스러움·방어적 뉘앙스)

다음 패턴은 PPT 슬로건·요약에서 **절대 쓰지 말 것**:

- **"~시대가 왔다"** — 블로그 톤. 대신 "~로 편입", "~이 일상화", "~단계 진입" 같은 명사형
- **"이 정도로 OO한 X가 지금 우리 손에 있다"** — 감탄사형. 팩트로 대체: "사람 X 수준이 상용 AI에 내장"
- **"이게 지금의 X"** — 공허한 수식. "X의 현주소", "X가 도달한 지점"으로 대체
- **"실제 수준/진짜 OO"** — "실제"는 방어적 강조어. 빼면 오히려 더 단정적으로 들림
- **명사+의+명사+의+명사** 체인 — "현재 AI의 실제 수준"처럼 "의"로 3단 연결되면 밋밋. 한 쪽을 형용사·수식구로 분해
- **감탄 부호 남발** — 슬라이드에 "!", "!!" 금지. 강조는 색·크기·em 태그로
- **"세상을 바꾸는", "혁신적인", "놀라운"** — 광고 카피. 구체적 수치·성과로 대체

### 어색한 직역·비유 금지 (한국어 자연스러움)

기술 용어를 설명할 때 **비유를 만들려 하지 말고 동작 자체를 서술**한다. 어색한 직역·과한 비유는 오히려 이해를 방해한다.

- **"맨손으로 묻기"** (zero-shot) — 비유가 어색. → "예시 없이 바로 질문"처럼 동작 서술
- **"디테일이 안 챙겨질까"** — "챙기다"는 사람 주어에만 자연스러움. 추상 명사에 쓰면 어색. → "디테일이 안 생길까"
- **"왜 나한테는 이럴까?"** — 주어가 모호. → "왜 내가 쓰면 이럴까?" / "왜 내가 원하는 답이 안 나올까?"
- **"~챙기는 워크플로우"** — 모호. → "~더하는" / "~완성하는"처럼 구체 동작

**체크:** 문장을 소리 내어 읽어봐서 걸리면 무조건 다시 쓴다. 의인화·비유는 직관적이지 않으면 동작 서술로 대체.

### 예시·콘텐츠는 학교급 중립으로

초등 연수용이라도 예시는 **초·중·고 공통으로 통하는 소재**를 우선한다. 특정 학년·학교급에만 맞는 디테일은 피한다.

- **학년 특정 금지** — "6학년 운동회", "1학년 받아쓰기"처럼 학년 박히면 다른 급에서는 공감대 없음. → "수학여행", "학부모 상담주간", "시험 안내" 같은 공통 소재
- **반 번호 표기** — "6-3반" 같은 구체 번호 대신 "○학년 ○반" 플레이스홀더
- **소재 선택 가이드** — 학부모 안내문, 학년부 회의, 평가/상담, 수행평가 등 학교급 무관 소재 우선

**체크리스트 (요약 문구 쓰기 전 자문):**
1. 동사로 끝나면 → 명사형으로 고치기
2. 수식어("실제", "진짜", "정말")가 들어가면 → 빼도 의미 살면 삭제
3. 앞에서 구체 수치를 말했다면 → 뒤에 "~수준" 같은 추상어 금지, 마찬가지로 구체적으로
4. 청중에게 감탄 강요하는 형태(~왔다, ~있다)면 → 팩트 서술형으로

## 디자인 금지 규칙 (사용자 피드백 기반)

- **`border-left` 절대 사용 금지** — 좌측 세로 테두리 강조는 AI 생성 느낌. quote-box, 인용, 강조 박스 등 어디서도 `border-left`로 포인트 주지 말 것. 대신 배경색, 전체 border, 또는 아이콘으로 차별화.
- **`border-top` 색상 포인트 바도 금지** — 카드 상단에 `border-top: 3px solid var(--pink)` 같은 색 바 추가 금지. "촌스러움"의 대표 유형. 카테고리 구분은 아이콘·배경 톤 변주로.
- **콘텐츠 슬라이드 여백 최소화** — 타이틀 슬라이드(첫 슬라이드) 제외하고 여백이 눈에 띄면 안 됨. 해결책:
  - 열(`.col`) 안 항목들에 `flex: 1` 추가해서 높이 채우기
  - 텍스트 크기를 `--ts` 대신 `--tb` 이상으로 크게
  - `grp-title`, `grp-desc`, `blist li`, `flow-title`, `flow-desc` 등 본문 텍스트는 `--tb` 기준으로
  - `flow-node` padding은 `clamp(1.4rem, 3.5vh, 2.8rem)` 이상으로 충분히
  - 카드 패딩도 충분히 (`clamp(1rem, 2vh, 1.5rem)` 이상)
