# 업무문서 라우팅

사용자의 요청 의도와 파일 확장자를 기준으로 처리 흐름을 먼저 결정한다.

## 기존 양식 채우기

- `.hwp`: 먼저 HWPX로 변환한 뒤 HWPX 양식 workflow를 적용한다. 한글 COM 사용이 가능하면 원본 HWP를 한글에서 직접 HWPX로 저장한 파일을 우선 사용하고, `scripts/convert_hwp.py` 변환본은 COM이 불가능할 때나 구조 분석 보조용으로 사용한다. 편집 후 최종 산출물은 다시 HWP로 저장하지 않고 `.hwpx`로 제공한다.
- `.hwpx`: `references/hwpx-forms.md`를 따른다.
- `.xls`, `.xlsx`: `references/xlsx-forms.md`를 따른다.
- `.ppt`, `.pptx`: 기존 발표자료 파일을 직접 수정해야 할 때만 PowerPoint workflow를 사용한다.

## 새 자료 만들기

- 신청서, 공문, 보고서, 이력서, 공적조서, 추천서, 계획서: HWPX 또는 문서형 산출물을 우선 고려한다.
- 명단, 집계표, 연수목록, 경력산출표, 예산표: XLSX를 우선 고려한다.
- 발표자료, 연수자료, 수업자료, 슬라이드, "PPT": HTML 기반 슬라이드를 기본값으로 만든다.
- 사용자가 명시적으로 "pptx", "파워포인트 파일", "PowerPoint"를 요구하거나 기존 `.pptx` 템플릿을 제공한 경우에만 PPTX를 만든다.

## 프로젝트 초기 세팅과 자료 정리

- 현재 폴더 또는 상위 프로젝트 폴더명이 `(AI)`로 끝나면 `references/project-setup.md`를 따른다.
- 최초 세팅 요청은 원문을 모두 열지 말고 폴더명, 파일명, 확장자를 기준으로 `docs/00_폴더지도.md`, `docs/01_분류기준.md`, `docs/02_자료목록.md`를 먼저 만든다.
- 파일은 `주분류`와 여러 `보조분류`로 분류한다. 실제 원본 폴더 구조는 그대로 둔다.
- 이후 문서 작성에서는 `docs/` Markdown 자료를 우선 읽는다. Markdown이 없거나 오래된 경우, 또는 현재 요청과 직접 관련된 경우에만 원본을 열어 갱신한다.

## 외부 단건 파일

- 사용자가 현재 작업공간 밖의 파일 경로를 직접 주면 외부 단건 파일로 처리하고 `references/project-setup.md`를 따른다.
- 외부 단건 파일은 `(AI)` 작업공간으로 복사하거나 `docs/`에 기본 등록하지 않는다.
- 원본은 덮어쓰지 않고, 결과물은 원본 파일과 같은 폴더에 `_완성본` 접미사로 저장한다.
- 같은 이름이 있으면 `_완성본2`, `_완성본3`처럼 번호를 붙인다.

## 공통 자료 우선순위

1. 현재 사용자 요청의 명시 지시
2. `docs/`의 정리된 Markdown 자료
3. `design.md` 또는 사용자가 제공한 디자인 기준 문서
4. PDF, 이미지, 기존 HTML/CSS 같은 디자인 레퍼런스
5. 원본 증빙/양식 파일

개인정보와 증빙 파일은 이 프로젝트 안에서만 사용하고, 배포용 스킬에는 포함하지 않는다.
