# 업무문서 라우팅

사용자의 요청 의도와 파일 확장자를 기준으로 처리 흐름을 먼저 결정한다. 기본 모델은 `산출물 형식 workflow + 문서 내용 규칙`이다.

## 기본 모델

- 사용자가 작업 대상 파일 또는 폴더 경로를 명시하면 현재 시작 폴더보다 그 대상 경로를 먼저 본다.
- 작업 대상 경로 또는 상위 폴더 중 하나가 `(AI)`로 끝나면 대소문자를 구분하지 않고 가장 가까운 `(AI)` 폴더를 기준 작업폴더로 삼는다.
- 명시된 작업 대상 경로가 없으면 현재 작업폴더와 그 상위 폴더를 같은 방식으로 확인한다.
- 모든 프로젝트 내부 경로는 기준 작업폴더 기준 상대경로로 해석한다.
- 산출물 형식 workflow: HWPX, XLSX, HTML처럼 파일 구조를 보존하고 검증하는 절차다.
- 문서 내용 규칙: 이력서, 공적조서, 신청서처럼 어떤 내용을 어떤 문체와 우선순위로 쓸지 정하는 보조 규칙이다.
- 이력서, 공적조서, 신청서는 독립 workflow가 아니라 보통 HWPX/XLSX workflow 위에 얹는 내용 규칙이다.

## 산출물 저장 위치

- 모든 수정본, 완성본, 제출용 파일은 기준 작업폴더 안의 `완성본/` 폴더에 저장한다.
- `완성본/` 폴더가 없으면 먼저 만든다.
- 원본 파일은 덮어쓰지 않는다.
- 파일명은 원본 이름 또는 문서명을 유지하되 `_완성본`, `_제출용`, `_검토본` 같은 접미사를 붙인다.
- 같은 이름이 이미 있으면 `_완성본2`, `_완성본3`처럼 번호를 붙인다.

## 기존 양식 채우기

- `.hwp`: 원본 표, 병합, 행 높이, 열 너비 보존을 최우선으로 한다. 한글 COM으로 원본 HWP를 HWPX로 빠르게 저장할 수 있으면 HWPX 양식 workflow를 적용한다. 변환이 멈추거나 실패하고 표 기반 양식이면 HWPML2X를 추출해 원본 표 셀만 채우고 `_원본표_완성본.hwp`로 저장한 뒤 필요하면 HWPX도 함께 저장한다. `md2hwpx.py`로 새 표를 재작성하는 방식은 기존 양식 채우기의 fallback으로 사용하지 않는다.
- `.hwpx`: `references/workflows/hwpx-forms.md`를 따른다.
- `.xls`, `.xlsx`: `references/workflows/xlsx-forms.md`를 따른다.
- `.ppt`, `.pptx`: 기존 발표자료 파일을 직접 수정해야 할 때만 PowerPoint workflow를 사용한다.
- 양식 성격이 이력서, 공적조서, 신청서이면 `references/teacher-admin-rules.md`에서 해당 내용 규칙도 함께 적용한다.

## 새 자료 만들기

- 신청서, 공문, 보고서, 회의록, 이력서, 공적조서, 추천서, 계획서: HWPX 또는 문서형 산출물을 우선 고려하고, 필요하면 `references/teacher-admin-rules.md`의 내용 규칙을 함께 적용한다.
- 명단, 집계표, 연수목록, 경력산출표, 예산표, 예산요구서: XLSX를 우선 고려하고, 필요하면 `references/teacher-admin-rules.md`의 내용 규칙을 함께 적용한다.
- 발표자료, 연수자료, 수업자료, 슬라이드, "PPT": HTML 기반 슬라이드를 기본값으로 만든다.
- 사용자가 명시적으로 "pptx", "파워포인트 파일", "PowerPoint"를 요구하거나 기존 `.pptx` 템플릿을 제공한 경우에만 PPTX를 만든다.

## 내용 규칙 매핑

- 이력서, 자기소개식 이력서, 경력기술서: `references/content-rules/resume.md`
- 공적조서, 공적요약서, 표창 추천서: `references/content-rules/achievement-statement.md`
- 신청서, 지원서, 참가신청서: `references/content-rules/application.md`
- 회의록, 협의록, 협의 결과 보고: `references/content-rules/meeting-minutes.md`
- 성립전 예산 요구서, 부서예산요구서, 예산표: `references/content-rules/budget-request.md`
- 공문, 보고서, 계획서, 추천서, 연수/경력 목록: 별도 규칙이 없으면 `references/content-rules/common.md`

## 프로젝트 초기 세팅과 자료 정리

- 작업 대상 경로, 현재 폴더, 또는 그 상위 폴더 중 하나의 이름이 `(AI)`로 끝나면 대소문자를 구분하지 않고 `references/project-setup.md`를 따른다. 예: `./양식(AI)/서명넣기/` 또는 `./양식(ai)/서명넣기/`는 모두 `양식(AI)` 작업공간 안의 하위 작업으로 본다.
- 최초 세팅 요청은 원문을 모두 열지 말고 폴더명, 파일명, 확장자를 기준으로 `docs/00_폴더지도.md`, `docs/01_분류기준.md`, `docs/02_자료목록.md`를 먼저 만든다.
- 파일은 `주분류`와 여러 `보조분류`로 분류한다. 실제 원본 폴더 구조는 그대로 둔다.
- 이후 문서 작성에서는 `docs/` Markdown 자료를 우선 읽는다. Markdown이 없거나 오래된 경우, 또는 현재 요청과 직접 관련된 경우에만 원본을 열어 갱신한다.

## 외부 단건 파일

- 사용자가 현재 작업공간 밖의 파일 경로를 직접 줬고 그 파일 경로와 상위 폴더에 `(AI)` 작업공간이 없으면 외부 단건 파일로 처리하고 `references/project-setup.md`를 따른다.
- 외부 단건 파일은 `(AI)` 작업공간으로 복사하거나 `docs/`에 기본 등록하지 않는다.
- 원본은 덮어쓰지 않고, 결과물은 원본 파일의 부모 폴더 안에 `완성본/` 폴더를 만들어 저장한다.
- 같은 이름이 있으면 `_완성본2`, `_완성본3`처럼 번호를 붙인다.

## 공통 자료 우선순위

1. 현재 사용자 요청의 명시 지시
2. `docs/`의 정리된 Markdown 자료
3. `design.md` 또는 사용자가 제공한 디자인 기준 문서
4. PDF, 이미지, 기존 HTML/CSS 같은 디자인 레퍼런스
5. 원본 증빙/양식 파일

개인정보와 증빙 파일은 이 프로젝트 안에서만 사용하고, 배포용 스킬에는 포함하지 않는다.
