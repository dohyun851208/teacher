# HTML 기반 발표자료

사용자가 발표자료, 수업자료, 연수자료, 슬라이드, PPT를 새로 만들어 달라고 하면 기본 산출물은 `.pptx`가 아니라 HTML 슬라이드다.

## 기본 원칙

- 기본 파일명은 `index.html`로 한다.
- 브라우저 전체화면 발표를 1차 사용 환경으로 본다.
- 필요하면 인쇄 CSS로 PDF 출력이 가능하게 만든다.
- 인터넷이 불안정한 교실을 고려해 가능하면 단일 HTML 또는 로컬 assets 구조를 사용한다.
- `.pptx`는 사용자가 명시적으로 요구하거나 기존 PowerPoint 파일을 제공했을 때만 만든다.

## 데스크톱 발표 기준

- 교사용 HTML 발표자료는 기본적으로 1920x1080 발표 화면을 기준으로 설계한다.
- 모바일 대응보다 데스크톱 발표 가독성과 화면 장악력을 우선한다.
- 16:9 화면에서 좌우를 넓게 쓰고, 콘텐츠가 중앙에 과도하게 모이지 않게 한다.
- 개발과 검증도 1920x1080을 우선 기준으로 한다.
- 다른 크기 대응이 필요하면 사용자가 명시적으로 요청했을 때 별도 처리한다.

## 교사용 발표자료 구성

- 제목/도입
- 학습 목표 또는 연수 목표
- 핵심 개념
- 예시와 비예시
- 활동 안내
- 단계별 실습
- 공유/정리
- 성찰 또는 exit ticket

## UI와 가독성

- 16:9 화면을 기본으로 한다.
- 특별한 의도가 없으면 주요 콘텐츠 덩어리는 슬라이드의 시각적 중앙에 둔다. 상단이나 하단으로 치우친 배치는 사용자가 요청했거나 레이아웃 이유가 분명할 때만 쓴다.
- 발표용 본문은 과밀한 문단보다 짧은 문장과 단계적 공개를 우선한다.
- 제목은 의미 단위로 직접 줄바꿈한다. 자동 줄바꿈에만 맡기지 않는다.
- 발표자료 헤드라인은 문장형 설명보다 명사형, 체언형, 짧은 종결을 우선한다.
- 예: `줄이는 방법을 봅니다`보다 `줄이는 방법`, `파일 작업으로`, `실행형 AI`처럼 슬라이드 제목답게 짧게 쓴다.
- 제목에 마침표를 붙일지는 디자인 의도로 통일한다. 붙인다면 짧고 선언적인 문장에만 쓴다.
- 한글 문장이 한 글자씩 튀어나오는 줄바꿈은 금지한다. `word-break: keep-all`, 적절한 폭, 수동 `<br>`로 의미 단위 줄바꿈을 보장한다.
- 제목, 본문, 보조 텍스트의 크기 위계를 명확히 둔다.
- 한 슬라이드에서 가장 중요한 문장 하나가 먼저 보이게 한다.
- 보조 설명 문장은 제목과 경쟁하지 않게 충분히 작게 둔다.
- 어색한 번역투나 기계적인 표현을 쓰지 않는다. 교사가 실제 연수에서 말해도 자연스러운 문장으로 쓴다.
- 축약 표현은 실제 행동이 분명하게 떠오르는지 확인한다. 대상, 장소, 행동을 생략해 어색해지면 풀어 쓴다.
- 예: `웹 AI와 오가며 작업`처럼 대상이 어색한 표현은 쓰지 않는다. `웹사이트를 반복해서 오가며 작업`처럼 실제 행동이 보이게 쓴다.
- 텍스트, 아이콘, 선, 강조 요소의 색은 최대 3가지로 제한한다: 검정, 파랑, 주황.
- 흰색 배경, 검정 배경처럼 화면의 기본 배경색은 위 색 개수 제한에서 제외한다.
- 검정 배경에서 쓰는 흰색 본문은 역상 표현으로 보고, 새 강조색으로 세지 않는다.
- 회색을 별도 색처럼 쓰지 않는다. 보조 텍스트와 구분선은 검정 또는 흰색의 투명도로 처리한다.
- 기본 조합은 검정과 파랑 2가지다.
- 검정은 본문과 구조, 파랑은 Codex, 도구 실행, 파일 처리, 선택 상태에 쓴다.
- 주황은 문제 상황, 전환점, 대비가 필요한 핵심 단어처럼 예외적으로만 쓴다.
- 한 슬라이드에서 주황을 쓰면 다른 강조를 줄여 주황이 한 번만 눈에 들어오게 한다.
- 강조 색은 중요한 단어, 단계 번호, 선택 상태처럼 의미가 있는 부분에만 쓴다.
- 새 강조색을 임의로 추가하지 않는다.
- 수업 활동 슬라이드는 학생이 바로 행동할 수 있게 과업, 시간, 산출물을 분명히 보이게 한다.
- QR, 링크, 타이머, 체크리스트, 교사용 메모 영역을 필요에 따라 만든다.
- 과도한 장식보다 교실에서 읽히는 대비, 여백, 크기를 우선한다.
- 의미 없는 배지, 태그, pill은 넣지 않는다. 발표자가 말하지 않아도 되는 제작 조건이나 내부 기준은 화면에서 제거한다.
- 예: 표지에 `HTML 발표자료`, `1920x1080` 배지를 넣는 것은 청중에게 의미가 없으면 삭제한다.

## 구성과 중복 제거

- 인접한 두 슬라이드가 같은 메시지를 반복하면 합친다.
- 개념 소개와 오늘의 목표가 겹치면 하나의 전환 슬라이드로 정리한다.
- 한 슬라이드에는 하나의 주장이 있어야 한다. 보조 문장은 그 주장을 돕는 역할만 한다.
- 발표자료는 문서가 아니라 말하기의 흐름이므로, 긴 설명보다 핵심 전환이 먼저 보이게 한다.
- 같은 단어를 반복해 설명하기보다 이전 방식과 새 방식의 차이를 분명히 보여준다.

## 근거와 통계

- 가격, 성능, 사용률, 벤치마크처럼 바뀔 수 있는 내용은 반드시 최신 자료를 확인하고 날짜 또는 출처를 남긴다.
- 통계 슬라이드는 추상적 주장보다 숫자 카드, 비교표, 순위, 변화율처럼 한눈에 보이는 형태를 우선한다.
- 벤치마크는 항목별로 결과가 달라질 수 있으므로 과장하지 않는다.
- 예: `가장 좋다`보다 `Terminal-Bench 2.0에서 GPT-5.5 82.7, Opus 4.7 69.4`처럼 지표와 수치를 함께 적는다.
- 가격 비교는 입력/출력 단가, 기준 날짜, 모델명을 분리해 쓴다.
- 출처 문장은 작게 두되, 발표자가 검토할 수 있을 만큼 구체적으로 적는다.

## 정보 위계

- 파일 경로, 폴더 구조, 체크리스트처럼 항목이 많은 슬라이드는 모든 텍스트를 같은 크기로 나열하지 않는다.
- 루트/그룹/항목/설명을 크기, 굵기, 색, 간격으로 구분한다.
- 긴 파일명은 그대로 나열하기보다 `docs/`, `references/` 같은 상위 단위와 역할 설명으로 요약한다.
- 예: `references/hwpx-forms.md`, `references/xlsx-forms.md`를 각각 같은 무게로 나열하기보다 `references/ - HWPX, XLSX, 발표자료 처리법`으로 묶는다.

## 애니메이션

- 애니메이션은 장식이 아니라 이목을 끌어야 하는 순간에만 사용한다.
- 한 슬라이드에는 하나의 주 애니메이션만 둔다.
- 제목, 핵심 오브젝트, 단계 카드 중 무엇을 먼저 보게 할지 결정한 뒤 그 요소에만 움직임을 준다.
- 기본 패턴은 짧은 fade/slide/scale 진입이다.
- 반복 애니메이션은 주의를 빼앗기므로 피한다. 필요한 경우 CTA나 현재 단계 표시처럼 기능이 있는 곳에만 약하게 사용한다.
- 발표자가 설명해야 할 본문이 흔들리거나 계속 움직이면 안 된다.
- `prefers-reduced-motion` 환경에서는 애니메이션을 끈다.

## 검증

- 로컬 브라우저로 열어 1920x1080에서 텍스트 겹침과 화면 밖 넘침이 없는지 확인한다.
- 가능하면 스크린샷으로 첫 화면, 활동 슬라이드, 긴 텍스트 슬라이드를 확인한다.
